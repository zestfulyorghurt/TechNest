# 个人技术社区搭建全流程

## 0. 文档说明

本文档用于梳理“个人技术社区 / 个人博客园”项目从需求、设计、技术方案、开发、测试、部署到维护的完整流程。

原始想法是通过搭建一个个人博客社区，把 Web 开发的整条链路打通，同时提供一个可以记录技术、生活、想法，并通过内容慢节奏交友的平台。

本文档在原有内容基础上做了以下完善：

1. 补充项目定位、目标用户、角色权限。
2. 拆清前台用户端、个人中心、作者侧、管理后台之间的边界。
3. 完善所有功能模块的设计，避免只停留在“模块名称”层面。
4. 补充页面清单、核心业务流程、接口方向、数据库方向。
5. 补充测试、部署、安全、数据统计、后期维护等容易遗漏的内容。

## 1. 项目背景与目标

### 1.1 项目背景

在完成一个 React 项目后，希望通过搭建自己的个人技术社区，把 Web 开发流程完整实践一遍，包括需求分析、UI 设计、前端开发、后端接口、数据库设计、测试、部署和维护。

项目不仅是一个个人博客，也希望具备一定社区属性。用户可以发布内容、阅读内容、评论互动、点赞收藏、关注作者、私信交流，从而形成一个以技术分享和生活记录为核心的小型社区。

### 1.2 项目目标

项目主要目标如下：

1. 建立一个可以长期维护的个人内容平台。
2. 支持文章发布、展示、编辑、审核、管理。
3. 支持用户注册、登录、个人资料维护。
4. 支持评论、点赞、收藏、关注、私信等用户互动。
5. 支持个人数据看板和运营总览看板。
6. 通过项目实践完整 Web 开发流程。

### 1.3 项目边界

第一版不建议一次性做成大型社区。建议先做可上线的 MVP，再逐步迭代。

第一版重点：

1. 用户注册登录。
2. 文章列表、文章详情、文章发布和编辑。
3. 评论、点赞、收藏。
4. 个人中心。
5. 基础数据统计。
6. 简单后台管理。

后续迭代：

1. 关注动态流。
2. 私信实时聊天。
3. 内容审核流。
4. 全文搜索。
5. 推荐系统。
6. 更完整的数据分析和运营看板。

## 2. 用户角色与权限设计

### 2.1 用户角色

| 角色 | 说明 | 主要能力 |
| :--- | :--- | :--- |
| 游客 | 未登录访问者 | 浏览公开文章、搜索文章、查看作者主页 |
| 注册用户 | 已登录用户 | 评论、点赞、收藏、关注、私信、维护个人资料 |
| 作者 | 发布内容的用户 | 发布文章、编辑自己的文章、查看个人数据、管理自己文章下的评论 |
| 管理员 | 平台管理者 | 管理用户、管理文章、审核内容、查看运营数据 |

### 2.2 权限规则

| 功能 | 游客 | 注册用户 | 作者 | 管理员 |
| :--- | :---: | :---: | :---: | :---: |
| 浏览公开文章 | 支持 | 支持 | 支持 | 支持 |
| 搜索文章 | 支持 | 支持 | 支持 | 支持 |
| 评论文章 | 不支持 | 支持 | 支持 | 支持 |
| 点赞 / 收藏 | 不支持 | 支持 | 支持 | 支持 |
| 关注作者 | 不支持 | 支持 | 支持 | 支持 |
| 发送私信 | 不支持 | 支持 | 支持 | 支持 |
| 发布文章 | 不支持 | 支持 | 支持 | 支持 |
| 编辑自己的文章 | 不支持 | 支持 | 支持 | 支持 |
| 删除他人内容 | 不支持 | 不支持 | 不支持 | 支持 |
| 查看个人数据 | 不支持 | 支持 | 支持 | 支持 |
| 查看运营总览 | 不支持 | 不支持 | 不支持 | 支持 |

### 2.3 容易遗漏的权限点

1. 用户只能编辑和删除自己的文章。
2. 用户只能删除自己的评论，管理员可以删除所有评论。
3. 未登录用户点击互动按钮时，应跳转登录或弹出登录提示。
4. 被封禁用户不能发布文章、评论、点赞、私信。
5. 草稿文章只能作者本人和管理员看到。
6. 审核未通过的文章不能在前台公开展示。

## 3. 开发流程总览

### 3.1 需求与设计阶段

1. 需求定义：明确项目目标、用户角色、功能范围、优先级。
2. 信息架构设计：确定首页、列表页、详情页、个人中心、后台页面的结构。
3. 原型设计：产出低保真原型或 HTML 原型。
4. UI 设计：产出 Figma 设计稿，明确颜色、字体、组件风格。

交付物：

1. 需求文档。
2. 页面清单。
3. 功能模块设计。
4. Figma 设计稿。

### 3.2 技术准备阶段

1. 技术选型：确定前端、后端、数据库、部署方案。
2. 数据库设计：设计用户、文章、评论、点赞、收藏、关注、消息、统计等表。
3. 接口定义：明确接口路径、请求参数、响应格式、错误码。
4. 环境准备：配置开发环境、数据库、对象存储、部署服务器。

交付物：

1. 技术方案文档。
2. 数据库 ER 图或表结构说明。
3. API 接口文档。
4. 环境变量说明。

### 3.3 开发与测试阶段

1. 前端开发：页面、组件、路由、状态管理、接口联调。
2. 后端开发：接口、业务逻辑、权限校验、数据处理。
3. 数据库开发：建表、索引、初始化数据。
4. 自测：开发者完成基础功能验证。
5. 联调：前后端根据接口文档联调。
6. 测试：功能测试、兼容性测试、权限测试、性能测试。

交付物：

1. 前端源码。
2. 后端源码。
3. 数据库脚本。
4. 测试用例。
5. Bug 记录。

### 3.4 部署与上线阶段

1. 打包构建。
2. 配置生产环境变量。
3. 初始化生产数据库。
4. 部署前端静态资源。
5. 部署后端服务。
6. 配置域名、HTTPS、反向代理。
7. 上线后冒烟测试。

交付物：

1. 部署文档。
2. 线上访问地址。
3. 生产环境配置说明。
4. 上线检查清单。

### 3.5 交付与维护阶段

1. 提交源码和文档。
2. 记录已完成功能和未完成功能。
3. 监控线上错误和性能。
4. 定期备份数据库。
5. 持续修复 Bug。
6. 规划小版本迭代。

## 4. 功能模块总览

原始文档中已有五个核心模块：用户认证模块、个人中心模块、内容管理模块、用户交互模块、数据分析模块。实际项目中还建议补充搜索分类、通知消息、后台管理、文件资源、安全与系统配置等支撑模块。

| 模块名称 | 核心功能 | 职责描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| 用户认证模块 | 注册、登录、退出、用户信息、权限校验 | 解决用户身份和访问权限问题 | P0 |
| 个人中心模块 | 我的文章、我的点赞、我的收藏、个人资料编辑 | 解决用户自我管理问题 | P0 |
| 内容管理模块 | 文章编辑、展示、状态、审核、管理 | 管理文章生命周期 | P0 |
| 用户交互模块 | 评论、点赞、收藏、关注、私信 | 支持用户和内容、用户和用户之间互动 | P0 / P1 |
| 数据分析模块 | 个人数据看板、运营总览看板 | 聚合统计数据并可视化展示 | P1 |
| 搜索分类模块 | 搜索、分类、标签、归档 | 提高内容查找效率 | P1 |
| 通知消息模块 | 评论通知、点赞通知、关注通知、私信提醒 | 让用户及时感知互动 | P1 |
| 后台管理模块 | 用户管理、文章审核、评论管理、数据查看 | 支撑平台运营和内容治理 | P1 |
| 文件资源模块 | 图片上传、头像上传、文章封面、Markdown 图片 | 管理静态资源和媒体文件 | P1 |
| 系统安全模块 | 密码加密、接口限流、XSS 防护、日志审计 | 保障系统安全稳定 | P0 |

1. P0：第一版必须完成，否则项目主流程不完整。

## 6. 核心业务流程

### 6.1 游客阅读流程

1. 用户进入首页。
2. 浏览最新文章或热门文章。
3. 进入文章详情页。
4. 查看文章正文、作者信息和评论。
5. 点击评论、点赞、收藏、关注时，系统提示登录。
6. 登录后回到当前文章继续操作。

### 6.2 用户互动流程

1. 用户登录。
2. 进入文章详情页。
3. 进行点赞、收藏、评论、关注作者等操作。
4. 后端校验登录状态和权限。
5. 写入对应业务表。
6. 更新文章互动计数。
7. 生成通知消息。
8. 数据分析模块记录行为事件。

### 6.3 作者发布文章流程

1. 作者进入文章编辑页。
2. 填写标题、摘要、正文、分类、标签、封面。
3. 保存草稿或提交发布。
4. 如果项目启用审核，则文章进入审核中状态。
5. 管理员审核通过后公开展示。
6. 文章上线后开始记录浏览、点赞、收藏、评论数据。
7. 作者可在个人数据看板查看文章表现。

### 6.4 私信流程

1. 用户进入作者主页或文章详情页。
2. 点击私信按钮。
3. 系统检查是否登录。
4. 创建或打开会话。
5. 用户发送消息。
6. 后端保存消息记录。
7. 接收方收到未读提醒。
8. 后续可升级为 WebSocket 实时通信。

### 6.5 管理员审核流程

1. 管理员登录后台。
2. 查看待审核文章或被举报内容。
3. 进入详情页检查内容。
4. 选择通过、驳回或下架。
5. 系统记录审核人、审核时间和审核原因。
6. 用户收到审核结果通知。

## 7. 功能模块详细设计

### 7.1 用户认证模块

#### 模块目标

负责用户身份认证、登录状态维护、权限控制，是所有互动、发布、管理功能的基础。

#### 核心功能

1. 用户注册。
2. 用户登录。
3. 用户退出。
4. 获取当前用户信息。
5. 修改密码。
6. 找回密码，可后续迭代。
7. 登录态过期处理。
8. 角色权限校验。

#### 前端功能点

1. 登录表单：账号、密码、验证码或图形验证。
2. 注册表单：用户名、邮箱、密码、确认密码。
3. 表单校验：必填、长度、格式、两次密码一致。
4. 登录成功后保存 token 或 session 状态。
5. 未登录访问受限页面时跳转登录。
6. 登录过期时清理本地状态并提示重新登录。

#### 后端接口方向

| 方法 | 接口 | 说明 |
| :--- | :--- | :--- |
| POST | `/api/auth/register` | 注册 |
| POST | `/api/auth/login` | 登录 |
| POST | `/api/auth/logout` | 退出 |
| GET | `/api/auth/me` | 获取当前登录用户 |
| PUT | `/api/auth/password` | 修改密码 |
| POST | `/api/auth/refresh` | 刷新登录态，可选 |

#### 数据表建议

`users` 用户表：

| 字段 | 说明 |
| :--- | :--- |
| id | 用户 ID |
| username | 用户名 |
| email | 邮箱 |
| password_hash | 加密后的密码 |
| avatar_url | 头像 |
| bio | 个人简介 |
| role | 用户角色 |
| status | 用户状态，正常、禁用、注销 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

#### 需要注意

1. 密码不能明文存储，必须加密后保存。
2. 登录接口需要防止暴力破解，可以增加验证码或限流。
3. token 不应长期不过期。
4. 用户名、邮箱需要唯一性校验。
5. 所有需要登录的接口都要做鉴权。

### 7.2 个人中心模块

#### 模块目标

让用户管理自己的资料、内容、互动记录和个人数据。

#### 核心功能

1. 查看和编辑个人资料。
2. 查看我的文章。
3. 查看我的草稿。
4. 查看我的点赞。
5. 查看我的收藏。
6. 查看我的关注和粉丝。
7. 查看我的评论。
8. 查看个人数据看板。

#### 页面设计

1. 个人中心首页：展示头像、昵称、简介、统计数据。
2. 资料编辑页：头像、昵称、简介、联系方式。
3. 我的文章页：文章状态筛选、编辑、删除、下架。
4. 我的收藏页：收藏列表、取消收藏。
5. 我的关注页：关注列表、取消关注。
6. 我的评论页：评论记录、跳转原文、删除评论。

#### 后端接口方向

| 方法 | 接口 | 说明 |
| :--- | :--- | :--- |
| GET | `/api/users/me` | 获取个人资料 |
| PUT | `/api/users/me` | 编辑个人资料 |
| GET | `/api/users/me/articles` | 我的文章 |
| GET | `/api/users/me/favorites` | 我的收藏 |
| GET | `/api/users/me/likes` | 我的点赞 |
| GET | `/api/users/me/follows` | 我的关注 |
| GET | `/api/users/me/fans` | 我的粉丝 |

#### 需要注意

1. 个人中心所有接口都需要登录。
2. 列表页需要分页，避免数据量大时加载慢。
3. 用户头像上传需要限制文件大小和格式。
4. 删除文章前需要二次确认。

### 7.3 内容管理模块

#### 模块目标

负责文章从创建、编辑、保存草稿、发布、审核、展示、下架到删除的完整生命周期。

#### 核心功能

1. 文章创建。
2. Markdown 或富文本编辑。
3. 保存草稿。
4. 发布文章。
5. 编辑文章。
6. 删除文章。
7. 文章状态管理。
8. 文章审核，可先做简化。
9. 文章详情展示。
10. 文章列表展示。

#### 文章状态设计

| 状态 | 说明 |
| :--- | :--- |
| draft | 草稿 |
| pending | 审核中 |
| published | 已发布 |
| rejected | 审核未通过 |
| offline | 已下架 |
| deleted | 已删除，逻辑删除 |

#### 文章字段建议

`articles` 文章表：

| 字段 | 说明 |
| :--- | :--- |
| id | 文章 ID |
| author_id | 作者 ID |
| title | 标题 |
| summary | 摘要 |

#### 7.4.1 评论功能

#### 7.5.5 数据分析注意事项

1. 不建议前端拉全量数据自己统计，应由后端聚合后返回。
2. 大数据量统计建议使用缓存或日统计表。
3. 阅读量需要防刷，可以按 IP、用户、时间窗口做去重。
4. 趋势图必须支持时间范围筛选。
5. 管理员运营数据和普通用户个人数据要严格区分权限。
6. 数据口径要明确，比如“日活用户”是当天登录过还是当天产生过行为。
7. 图表要考虑空数据状态。

#### 数据分析模块验收标准

1. 个人看板只能看到自己的数据。
2. 管理员才能看到全站运营数据。
3. 点赞、评论、收藏等数据和实际业务记录一致。
4. 切换时间范围后图表和卡片同步变化。
5. 数据为空时页面有友好提示。
6. 图表在移动端不重叠、不溢出。

1. 密码加密存储。
2. 登录接口限流。
3. 防止 XSS，尤其是文章正文和评论内容。
4. 防止 CSRF，取决于登录态方案。
5. 接口权限校验。
6. 文件上传安全。
7. 敏感操作日志。
8. 数据库备份。
9. 错误信息不要暴露内部细节。
10. 生产环境使用 HTTPS。

#### 前端注意

1. 不在前端存储敏感信息。
2. 接口报错要统一处理。
3. 富文本或 Markdown 渲染需要安全过滤。
4. token 过期要统一跳转登录。

#### 后端注意

1. 所有写操作必须鉴权。
2. 所有管理员接口必须校验角色。
3. 数据库查询避免 SQL 注入。
4. 上传文件需要校验 MIME 类型和扩展名。
5. 日志中不要打印密码、token 等敏感数据。

## 9. API 设计规范建议

### 9.1 响应格式

建议统一接口响应格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

分页响应建议：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "page": 1,
    "pageSize": 10,
    "total": 100
  }
}
```

### 9.2 常见错误码

| 错误码 | 说明 |
| :--- | :--- |
| 0 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或登录过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 重复操作 |
| 500 | 服务器内部错误 |

### 9.3 接口设计注意

1. 列表接口必须支持分页。
2. 查询接口应支持排序和筛选。
3. 写操作需要鉴权。
4. 删除操作优先考虑逻辑删除。
5. 错误返回要让前端能明确展示提示。

## 10. 技术选型建议

如果团队还没有最终确定技术栈，可以采用以下方案。

### 10.1 前端

1. React：构建前端页面和组件。
2. TypeScript：提高类型安全，可选但推荐。
3. Vite：项目构建工具。
4. React Router：前端路由。
5. Zustand 或 Redux Toolkit：状态管理。
6. Axios：接口请求。
7. ECharts 或 Recharts：数据可视化。
8. Markdown 编辑器：文章编辑。
9. Ant Design 或自定义组件库：后台和表单页面。

### 10.2 后端

可以选择其中一种：

1. Node.js + Express / NestJS。
2. Java + Spring Boot。
3. Python + FastAPI。

如果目的是快速打通 Web 全链路，推荐 Node.js + Express 或 NestJS，与前端 JavaScript 技术栈更统一。

### 10.3 数据库与中间件

1. MySQL 或 PostgreSQL：存储业务数据。
2. Redis：缓存热门文章、统计结果、验证码、限流数据。
3. 对象存储：保存图片文件，第一版也可以先存在服务器本地。
4. Nginx：反向代理和静态资源服务。

### 10.4 部署

1. 前端构建后部署为静态资源。
2. 后端部署为常驻服务。
3. 数据库单独部署。
4. 使用环境变量管理数据库连接、JWT 密钥、上传路径等配置。
5. 配置 HTTPS。

## 15. 你的负责模块建议拆分

你当前需要负责用户交互模块和数据分析模块，建议按下面方式拆任务。

### 15.1 用户交互模块任务

第一优先级：

2. 发表评论。

4. 点赞和取消点赞。
5. 收藏和取消收藏。

第三优先级：

1. 评论回复。
2. 评论点赞。
3. 举报评论。

第一优先级：

## 16. 总结

这个项目的核心不是只做一个博客页面，而是练习完整 Web 项目链路。第一版应该先保证“能注册、能登录、能发文章、能看文章、能互动、能看到基础数据”，后续再逐步增强社区和运营能力。

建议开发时按以下顺序推进：

1. 先打通用户认证。
2. 再打通文章发布和展示。
3. 然后做评论、点赞、收藏。
4. 再做个人中心和个人数据。
5. 最后补关注、私信、通知、后台和运营看板。
