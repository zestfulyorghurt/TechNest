## 1. 项目概述

### 1.1 项目背景

个人技术社区搭建背景：

- 在做完一个 React 项目后，想要使用项目中的经验去搭建一个自己的个人技术社区。
- 搭建个人博客想把 Web 开发的整条链路打通，经历一下 Web 开发的每一个流程，让自己能够更好的进行 Web 开发工作。
- 搭建个人博客想把自己想要记录的内容放到自己的网站当中去，更好的整理自己的工作或者生活内容。
- 希望大家可以在博客园中分享自己，在当今交友困难的时代，希望能做到一个通过分享技术、或者分享生活，来慢节奏交友的博客园。

### 1.2 项目目标

- 建立一个可以长期维护的个人内容平台。
- 支持文章发布、展示、编辑、审核、管理。
- 支持用户注册、登录、个人资料维护。
- 支持评论、点赞、收藏、关注、私信等用户互动。
- 支持个人数据看板和运营总览看板。
- 通过项目实践完整 Web 开发流程。

### 1.3 项目边界

**第一版重点（MVP）：**

1. 用户注册登录
2. 文章列表、文章详情、文章发布和编辑
3. 评论、点赞、收藏
4. 个人中心
5. 基础数据统计
6. 简单后台管理

**后续迭代：**

1. 关注动态流
2. 私信实时聊天
3. 内容审核流
4. 全文搜索
5. 推荐系统
6. 更完整的数据分析和运营看板


## 2. 用户认证模块 - 注册

> 前置条件：用户进行注册前，需勾选同意《用户协议》及《隐私政策》，未勾选时注册按钮不可用。

### 2.1 手机号注册

**步骤：**

1. 用户输入手机号 → 点击“获取验证码” → 系统发送 6 位数字验证码至该手机号。
2. 用户填写验证码 → 验证通过后，自动进入下一步。
3. 用户填写**昵称**和**密码** → 点击“注册”完成。

**规则：**

- 手机号需为有效号码，且**在全平台唯一**（已被注册或绑定的手机号不可再次使用）。
- 昵称不可为空，长度 2-12 个字符，支持中英文、数字、下划线。
- 密码长度 8-20 位，至少包含字母和数字。
- 密码用于手机号换绑后的备用登录方式。

**错误提示：**

| 场景                | 提示文案                                  |
| :------------------ | :---------------------------------------- |
| 手机号已被注册/绑定 | “该手机号已被注册，请直接登录”            |
| 验证码错误/过期     | “验证码错误” / “验证码已过期，请重新获取” |
| 昵称已被占用        | “该昵称已被占用，请更换一个”              |
| 密码不合规          | “密码长度需为 8-20 位，且包含字母和数字”  |

### 2.2 邮箱注册

**步骤：**

1. 用户输入邮箱 → 点击“获取验证码” → 系统发送 6 位数字验证码至该邮箱。
2. 用户填写验证码 → 验证通过后，自动进入下一步。
3. 用户填写**昵称**和**密码** → 点击“注册”完成。

**规则：**

- 邮箱需为有效格式，且**在全平台唯一**（已被注册或绑定的邮箱不可再次使用）。
- 昵称和密码规则同手机号注册。

**错误提示：**

| 场景              | 提示文案                                  |
| :---------------- | :---------------------------------------- |
| 邮箱已被注册/绑定 | “该邮箱已被注册，请直接登录”              |
| 验证码错误/过期   | “验证码错误” / “验证码已过期，请重新获取” |
| 昵称已被占用      | “该昵称已被占用，请更换一个”              |
| 密码不合规        | “密码长度需为 8-20 位，且包含字母和数字”  |

### 2.3 第三方社交账号注册

**支持平台：** 微信、QQ、支付宝、GitHub、Google

**步骤：**

1. 用户点击第三方图标 → 跳转至第三方授权页面。
2. 用户确认授权后，系统获取第三方账号的 `openid`、昵称、头像等信息。
3. 首次授权时，系统自动创建账号，使用第三方昵称作为默认昵称（如重名则自动追加随机后缀）。

**规则：**

- 一个第三方账号（`openid`/`unionid`）**在全平台唯一**，不可同时绑定多个本地账号。
- 创建账号时，如果第三方返回的昵称与已有用户重名，系统自动在昵称后追加随机后缀（如 `张三_wechat_a1b2`）。
- 用户注册成功后，可在个人中心修改昵称、绑定手机号或邮箱。
- **无需额外设置密码**，后续登录直接使用第三方授权即可。

**错误提示：**

| 场景               | 提示文案                                 |
| :----------------- | :--------------------------------------- |
| 第三方授权失败     | “授权失败，请稍后重试”                   |
| 第三方账号已被绑定 | “该第三方账号已绑定其他账号，请直接登录” |


## 3. 用户认证模块 - 登录

### 3.1 手机号登录

**方式一：验证码登录（推荐）**

- 用户输入手机号 → 点击“获取验证码” → 填写验证码 → 点击登录。
- 适用于日常登录场景。

**方式二：密码登录**

- 用户输入手机号 + 密码 → 点击登录。
- 适用于手机号已更换、无法接收验证码的备用场景。

**规则：**

- 验证码 5 分钟内有效。
- 密码错误超过 5 次，账号将锁定 15 分钟。

**错误提示：**

| 场景            | 提示文案                                  |
| :-------------- | :---------------------------------------- |
| 手机号未注册    | “该手机号尚未注册，请先完成注册”          |
| 验证码错误/过期 | “验证码错误” / “验证码已过期，请重新获取” |
| 密码错误        | “密码错误，您还有 X 次尝试机会”           |
| 账号已锁定      | “账号已被锁定，请 15 分钟后重试”          |

### 3.2 邮箱登录

**方式：** 用户输入邮箱 + 密码 → 点击登录。

**规则：**

- 密码错误超过 5 次，账号将锁定 15 分钟。

**错误提示：**

| 场景       | 提示文案                         |
| :--------- | :------------------------------- |
| 邮箱未注册 | “该邮箱尚未注册，请先完成注册”   |
| 密码错误   | “密码错误，您还有 X 次尝试机会”  |
| 账号已锁定 | “账号已被锁定，请 15 分钟后重试” |

### 3.3 第三方社交账号登录

**支持平台：** 微信、QQ、支付宝、GitHub、Google

**步骤：**

1. 用户点击第三方图标 → 跳转至第三方授权页面。
2. 用户确认授权后，系统校验该第三方账号是否已绑定本地账号。
   - 已绑定 → 直接登录成功。
   - 未绑定 → 自动创建新账号并登录（流程同第三方注册）。

**规则：**

- 一个第三方账号只能绑定一个本地账号。
- 登录成功后，系统返回登录态（如 JWT token）。

**错误提示：**

| 场景                     | 提示文案                                         |
| :----------------------- | :----------------------------------------------- |
| 第三方授权失败           | “授权失败，请稍后重试”                           |
| 第三方账号已绑定其他账号 | “该第三方账号已绑定其他账号，请使用对应账号登录” |

| :------------- | :--------- | :------------------------------------------------- |
| **手机号**     | 全平台唯一 | 已被任一账号注册或绑定的手机号，不可再次注册或绑定 |
| **邮箱**       | 全平台唯一 | 已被任一账号注册或绑定的邮箱，不可再次注册或绑定   |
| **第三方账号** | 全平台唯一 | 已被任一账号绑定的第三方账号，不可再次绑定其他账号 |
| **昵称**       | 允许重复   | 系统通过 `user_id` 区分用户身份                    |


## 5. 个人中心模块

个人中心是用户管理自身内容、行为和账户信息的核心入口。

### 5.1 博客管理

用户对自己发布的博客进行统一管理。

**功能列表：**

- **查看我的博客**：以列表形式展示自己发布的所有博客，支持分页加载。
- **删除博客**：删除指定的博客。删除后该博客不再公开可见，且不可恢复（需二次确认）。
- **编辑博客**：进入博客编辑页，修改标题、正文、分类、标签等信息后重新发布。已发布的博客修改后是否需要重新审核，由后台审核规则决定。
- **置顶博客**：将指定博客置顶到个人主页顶部，最多支持 3 篇置顶（数量可配置）。置顶博客在列表中优先展示。
- **更改排序**：支持按创建时间、更新时间、浏览量等方式对博客列表进行排序。

**规则说明：**

- 已删除的博客不占用用户博客配额。
- 置顶操作仅影响个人主页的展示顺序，不影响全站列表的排序逻辑。

### 5.2 点赞管理

**功能列表：**

- **查看点赞列表**：展示用户所有点赞过的博客，按点赞时间倒序排列。
- **取消点赞**：点击后可取消对该博客的点赞，点赞数相应减 1。

**规则说明：**

- 取消点赞后，该博客从点赞列表中移除。
- 支持再次点赞（点赞数重新加 1）。

### 5.3 收藏管理

**功能列表：**

- **查看收藏列表**：展示用户所有收藏过的博客，按收藏时间倒序排列。
- **取消收藏**：点击后可取消对该博客的收藏。

**规则说明：**

- 取消收藏后，该博客从收藏列表中移除。

### 5.4 评论管理

**功能列表：**

- 用户回顾自己的评论。
- 可以跳转到评论过的博客界面中去。

### 5.5 附件管理

**功能列表：**

- 如果用户为 VIP，可以上传附件。
- 追加一个附件的一览，方便用户管理自己的附件。
- 可以快捷对上传过的附件进行下载。

### 5.6 VIP信息

**已开通 VIP 时：**

- 显示当前 VIP 套餐名称（如“年度会员”）。
- 显示成为 VIP 的日期及到期日期。
- 当 VIP 距离到期不足 7 天时，在页面顶部显示续费提醒横幅。
- 提供 **续费** 按钮，跳转至续费流程。

**未开通 VIP 时：**

- 显示 VIP 套餐列表（包含各套餐的权益对比和价格）。
- 提供 **开通 VIP** 按钮，跳转至支付流程。

**套餐内容示例：**

| 权益项           | 普通用户 | VIP 用户 |
| :--------------- | :------: | :------: |
| 查看付费文章     |    ❌     |    ✅     |
| 下载附件/源码    |    ❌     |    ✅     |
| 上传文件大小限制 |   10MB   |  100MB   |
| 博客置顶数       |   0 篇   |   3 篇   |

### 5.7 个人资料管理

**可编辑字段：**

| 字段   | 说明                                                    |
| :----- | :------------------------------------------------------ |
| 头像   | 支持上传图片，自动裁剪为 1:1 比例，建议尺寸 200x200px   |
| 昵称   | 2-12 个字符，支持中英文、数字、下划线（全平台允许重名） |
| 生日   | 日期选择器，格式 YYYY-MM-DD                             |
| 职业   | 自由文本输入，如“前端工程师”                            |
| 居住地 | 省/市 二级联动选择器                                    |
| 手机号 | 需验证原手机号后方可修改（换绑流程见账号安全）          |
| 邮箱   | 需验证原邮箱后方可修改（换绑流程见账号安全）            |

**账号注销：**

- 提供 **注销账号** 按钮。
- 点击后触发二次确认弹窗，用户需阅读注销须知并再次确认。
- 确认后进入**冻结期**（如 7 天），期间用户可登录并撤销注销申请。
- 冻结期结束后，账号及关联数据（博客、评论、点赞、收藏等）将被**永久删除且不可恢复**。


## 6. 内容管理模块

### 6.1 博客列表页

主页展示所有已审核通过的博客。

- **排序**：支持按浏览量、更新时间、创建时间、点赞数、收藏数、评论数排序（正序/倒序）。默认按创建时间倒序。
- **检索**：支持按关键字（标题/作者昵称）搜索，支持按时间段筛选，支持按博客的类型筛选。
- **交互**：点击博客卡片进入详情页。

### 6.2 博客详情页

- 展示博客完整内容（标题、正文、作者、发布时间等）。
- 显示浏览量、点赞数、收藏数、评论数。
- 登录用户可点赞、收藏、评论。

### 6.3 博客编写页

用户创建和编辑博客的核心界面，对标 CSDN 博客编辑器体验。

**页面布局：**

采用左右两栏布局（可折叠/收起）：

- **左栏（编辑区）**：Markdown 编辑器，支持实时预览。
- **右栏（设置区）**：博客元信息配置面板。

**编辑区功能：**

- **Markdown 编辑器**：
  - 支持标准 Markdown 语法（标题、列表、代码块、表格、引用、图片、链接等）。
  - 提供**工具栏**（加粗、斜体、插入链接、插入图片、插入代码块等快捷按钮）。
  - 支持**快捷键**（如 `Ctrl+B` 加粗，`Ctrl+K` 插入链接）。
  - 支持**拖拽上传图片**（直接拖入编辑器区域即可上传并插入图片链接）。
- **实时预览**：
  - 编辑区右侧（或下方）同步渲染 Markdown 为 HTML 预览。
  - 预览区样式与博客详情页一致，所见即所得。
- **全屏模式**：支持编辑器全屏写作，沉浸式体验。
- **自动保存**：
  - 每 30 秒自动保存草稿至本地（或服务端）。
  - 页面关闭前如有未保存内容，浏览器提示“确认离开？”。

**设置区功能：**

- **博客标题**：输入框，必填，长度 5-100 个字符。
- **分类**：下拉选择或输入新建分类（如“前端”、“后端”、“生活随笔”等）。
- **标签**：输入标签后回车添加，最多 5 个标签（如“React”、“TypeScript”）。
- **封面图**：上传或从媒体库选择封面图片（建议尺寸 16:9）。
- **文章类型**：
  - **公开**：所有人可见（需审核通过）。
  - **私密**：仅自己可见（无需审核）。
  - **付费**：VIP 用户可查看（需设置价格或积分）。
- **摘要**：自动从正文截取前 200 字作为摘要，也支持手动编辑。
- **发布设置**：
  - **立即发布**：提交后进入审核流程（公开文章）或直接发布（私密文章）。
  - **定时发布**：设置未来某个时间自动发布（仅限公开文章）。

**交互流程：**

| 用户操作              | 系统处理                                                     |
| :-------------------- | :----------------------------------------------------------- |
| 进入编写页            | 如果是编辑已有博客 → 加载已有内容；如果是新建博客 → 加载空编辑器 |
| 编写内容 / 设置元信息 | 每 30 秒自动保存草稿；实时渲染预览区                         |
| 点击“发布”按钮        | 校验：标题、正文、分类是否为空 → 全部通过则提交；公开文章状态为“待审核”，私密文章为“已通过”，付费文章为“待审核”；任一校验失败则提示对应错误信息 |
| 点击“存草稿”按钮      | 保存当前内容，状态为“草稿”；提示“草稿已保存”                 |
| 点击“取消/返回”按钮   | 如有未保存内容 → 弹窗确认                                    |

**规则说明：**

- 公开文章发布后需经管理员审核，审核通过后方可公开可见。
- 私密文章发布后直接可见（仅作者本人），无需审核。
- 付费文章仅 VIP 用户可查看完整内容，普通用户仅可查看摘要。
- 定时发布文章在到达设定时间前，状态为“草稿”，到达后自动提交审核。
- 编辑已发布文章时，如果修改了正文或标题，需重新提交审核（状态变为“待审核”）。

**错误提示：**

| 场景             | 提示文案                         |
| :--------------- | :------------------------------- |
| 标题为空         | “请填写博客标题”                 |
| 正文为空         | “请填写博客内容”                 |
| 分类未选择       | “请选择博客分类”                 |
| 标签超过 5 个    | “标签最多添加 5 个”              |
| 保存失败         | “草稿保存失败，请检查网络后重试” |
| 发布失败         | “发布失败，请稍后重试”           |
| 定时时间早于当前 | “定时发布时间不能早于当前时间”   |

### 6.4 博客一览管理页（管理员）

管理员管理全站博客。

- **展示**：显示全站所有博客，含状态（待审核 / 已打回 / 已通过 / 草稿）。
- **排序**：同 6.1。
- **检索**：支持按标题、作者昵称、作者 ID、时间段、状态检索（多条件组合，AND 关系）。
- **交互**：
  - 点击标题/“详情” → 跳转前台详情页。
  - 仅“待审核”的博客显示“审核”按钮 → 进入审核页面（6.5）。

### 6.5 审核页面（管理员）

- **展示**：博客完整内容及当前状态（仅“待审核”可进入）。
- **操作**：
  - 审核状态（必选）：已通过 / 已打回 / 待审核
  - 审核批语（可选）：限 500 字
  - 点击“提交”完成审核
- **规则**：
  - 审核后作者可在个人中心查看结果及批语。
  - 已打回的博客，作者修改后可重新提交（状态变为“待审核”）。
  - 审核操作需记录日志（操作人、时间、原状态、目标状态、批语）。


## 7. 用户交互模块

### 7.1 模块概述

用户交互模块是社区的核心互动引擎，负责支撑用户与内容之间、用户与用户之间的各种互动行为。该模块让用户不仅仅是内容的消费者，更是社区氛围的参与者和创造者。

通过评论、点赞、收藏、关注、私信等功能，用户可以对优质内容表达认可、与作者建立连接、与其他用户进行交流，从而形成社区的社交网络和内容生态。

该模块的所有互动行为，同时也是数据分析模块的重要数据来源。

### 7.2 评论功能

**功能描述：**

用户在阅读文章后，可以在文章详情页的评论区发表自己的看法、提出问题或与作者及其他读者交流。评论是社区中最基础、最活跃的互动形式。

**发表评论：**

- 用户可以在文章详情页的评论区输入框中撰写评论内容。
- 评论内容需为非空文本，且长度限制在 1 到 1000 个字符之间。
- 用户点击“发布”或“提交”按钮后，评论立即发表。
- 评论成功后，评论区列表应自动刷新，新评论出现在列表顶部（或底部，由排序规则决定），同时文章下方的评论数量应实时增加。
- 未登录用户尝试发表评论时，系统应引导其先完成登录，或弹出登录窗口。

**查看评论列表：**

- 文章详情页应展示该文章下所有已通过审核的评论。
- 评论列表默认按创建时间倒序排列（最新评论在前）。
- 每条评论需展示：评论者的头像、昵称、评论内容、发布时间。
- 评论列表应支持分页加载或“加载更多”功能，避免一次性加载过多数据影响页面性能。

**删除自己的评论：**

- 用户可以在自己的评论上看到“删除”操作入口。
- 点击删除后，系统应弹出二次确认弹窗，防止误操作。
- 确认删除后，该评论从列表中移除，同时文章评论数量减一。
- 已删除的评论不再对任何人可见（包括作者本人），但数据可在后台保留用于审计。
- 用户只能删除自己发布的评论，不能删除他人评论。

**管理员删除评论：**

- 管理员可以在文章详情页或后台评论管理列表中删除任何不当评论。
- 管理员删除评论时需记录删除日志。
- 管理员删除评论后，该评论从公开展示中移除，同时文章评论数量减一。

**评论内容安全：**

- 评论内容需要经过基本的敏感词过滤或安全检测，防止恶意内容、广告或违规信息。
- 被系统标记为违规的评论不予发布，并提示用户修改内容。
- 评论内容在展示时需进行 XSS 防护处理，防止恶意脚本注入。

### 7.3 点赞功能

**功能描述：**

用户可以通过点赞功能对自己认可或喜欢的文章表达肯定。点赞是一种轻量级的正向反馈，能够激励作者持续创作优质内容，同时也能帮助其他读者快速识别受欢迎的文章。

**点赞文章：**

- 用户可以在文章详情页的指定区域（如文章底部或侧边栏）点击点赞按钮，对当前文章表达认可。
- 点赞按钮应使用醒目的图标（如爱心或大拇指）进行展示，并显示当前文章的累计点赞数量。
- 点击点赞按钮后，点赞数量应立即加一，同时按钮切换为“已点赞”状态（如爱心变为红色或实心填充）。
- 同一个用户对同一篇文章只能点赞一次，重复点击不应重复计数。
- 未登录用户尝试点赞时，系统应引导其先完成登录，或弹出登录窗口。

**取消点赞：**

- 用户对已点赞的文章可以随时取消点赞。
- 点击已点赞状态下的按钮，点赞数量应立即减一，同时按钮恢复为“未点赞”状态（如爱心变为空心）。
- 取消点赞后，用户可以再次对同一篇文章进行点赞。

**点赞状态展示：**

- 用户访问文章详情页时，系统应准确展示当前用户对该文章的点赞状态（已赞/未赞）。
- 点赞数量应保持实时准确，与实际的点赞记录数一致。
- 文章列表页中的每篇文章卡片也应显示对应的点赞数量。

### 7.4 收藏功能

**功能描述：**

收藏功能让用户可以将感兴趣的文章保存到自己的收藏夹中，方便日后回顾和查阅。收藏是个人知识管理的重要工具，与点赞不同，收藏更多体现的是内容的长期价值和用户的保存意愿。

**收藏文章：**

- 用户可以在文章详情页点击收藏按钮，将当前文章保存到自己的收藏夹中。
- 收藏按钮应显示当前文章的累计收藏数量。
- 点击收藏后，收藏数量应立即加一，同时按钮切换为“已收藏”状态。
- 同一个用户对同一篇文章只能收藏一次，重复点击不应重复计数。
- 未登录用户尝试收藏时，系统应引导其先完成登录，或弹出登录窗口。

**取消收藏：**

- 用户对已收藏的文章可以随时取消收藏。
- 点击已收藏状态下的按钮，收藏数量应立即减一，同时按钮恢复为“未收藏”状态。

**查看我的收藏列表：**

- 用户可以在个人中心中进入“我的收藏”页面。
- 该页面以列表形式展示用户所有收藏过的文章，按收藏时间倒序排列（最新收藏的在前）。
- 每篇收藏文章应展示：文章标题、作者昵称、发布时间、简要摘要、阅读量及点赞量等基本信息。
- 点击文章标题可跳转至对应的文章详情页。
- 收藏列表支持分页加载，避免数据量过大时影响加载速度。

**在收藏列表中取消收藏：**

- 用户可以在“我的收藏”列表中直接取消对某篇文章的收藏，无需跳转到文章详情页。
- 取消收藏后，该文章立即从收藏列表中移除。

### 7.5 关注功能

**功能描述：**

关注功能让用户可以订阅自己感兴趣的创作者，建立长期的阅读关系。关注是社区社交网络构建的基础，通过关注关系，用户可以及时获取关注作者的最新动态，平台也可以基于关注关系进行内容推荐。

**关注作者：**

- 用户可以在作者主页或文章详情页的作者信息区域点击“关注”按钮，关注该作者。
- 关注按钮应显示该作者的当前粉丝数量。
- 点击关注后，粉丝数量应立即加一，同时按钮切换为“已关注”状态（如“关注”变为“已关注”或“取消关注”）。
- 同一个用户不能重复关注同一个作者。
- 用户不能关注自己。
- 未登录用户尝试关注时，系统应引导其先完成登录，或弹出登录窗口。

**取消关注：**

- 用户对已关注的作者可以随时取消关注。
- 点击“已关注”或“取消关注”按钮，粉丝数量应立即减一，同时按钮恢复为“关注”状态。
- 取消关注后，该作者不再出现在用户的关注列表中。

**查看我的关注列表：**

- 用户可以在个人中心中进入“我的关注”页面。
- 该页面以列表形式展示用户所有关注的作者，按关注时间倒序排列。
- 每个关注项应展示：作者的头像、昵称、个人简介、粉丝数量。
- 点击作者头像或昵称可跳转至该作者的主页。
- 关注列表支持分页加载。

**查看我的粉丝列表：**

- 用户可以在个人中心中进入“我的粉丝”页面。
- 该页面以列表形式展示所有关注了当前用户的读者，按关注时间倒序排列。
- 每个粉丝项应展示：粉丝的头像、昵称、个人简介。
- 点击粉丝头像或昵称可跳转至其个人主页（如果对方公开了主页）。
- 粉丝列表支持分页加载。

**关注状态展示：**

- 用户访问作者主页或文章详情页时，系统应准确展示当前用户对该作者的关注状态（已关注/未关注）。

### 7.6 私信功能

**功能描述：**

私信功能允许用户之间进行一对一的私下交流，是社区中深度沟通和建立联系的重要途径。不同于公开的评论区，私信提供了更私密、更直接的对话空间，用户可以就共同感兴趣的话题进行深入探讨、进行技术交流、或建立友谊。

**发起私信：**

- 用户可以在作者主页或文章详情页的作者信息区域找到“私信”或“发消息”的入口。
- 点击后，进入与该作者的私信聊天界面，或者新建一个会话。
- 未登录用户尝试发送私信时，系统应引导其先完成登录。

**发送消息：**

- 在私信聊天界面中，用户可以在输入框中撰写消息内容。
- 消息内容需为非空文本，长度限制在 1 到 2000 个字符之间。
- 点击“发送”按钮后，消息立即发送，并显示在聊天窗口中。
- 发送成功后，输入框自动清空，方便用户发送下一条消息。
- 用户不能给自己发送私信。
- 被封禁或禁言的用户不能发送私信。

**会话列表：**

- 用户可以在个人中心中进入“私信中心”或“消息”页面。
- 该页面展示用户的所有私信会话列表，按最后一条消息的时间倒序排列（最新消息的会话在前）。
- 每个会话项应展示：对方用户的头像和昵称、最后一条消息的内容摘要、最后一条消息的发送时间。
- 如果会话中有未读消息，会话项应显示未读消息数量角标。

**查看消息记录：**

- 用户点击某个会话后，进入聊天窗口，可查看与该用户的所有历史消息记录。
- 消息记录按时间正序排列（最早的消息在前，最新的在后），符合日常聊天习惯。
- 消息记录支持分页加载或滚动加载（向上滚动加载更早的消息），方便查看历史对话。
- 每条消息应展示：发送者头像、消息内容、发送时间。

**标记已读：**

- 用户进入某个会话的聊天窗口后，该会话中的所有未读消息应自动标记为已读。
- 标记已读后，会话列表中的未读角标消失，未读消息总数相应减少。
- 消息的已读/未读状态应准确反映用户的阅读情况。

**未读消息提醒：**

- 系统应在页面顶部的导航栏或用户头像旁显示未读私信的总数量（红点或数字角标）。
- 当用户收到新私信时，未读数量应实时更新（第一版可通过轮询或页面刷新时更新，后续可升级为 WebSocket 实时推送）。
- 未读数量应准确反映所有会话中未读消息的总和。

### 7.7 通用规则与约束

**登录要求：**

评论、点赞、收藏、关注、私信等所有互动操作，均要求用户处于登录状态。未登录用户点击相关按钮或操作入口时，系统应：

- 跳转至登录页面，登录成功后返回原页面并继续之前未完成的操作；
- 或弹出登录窗口/模态框，用户登录后无需刷新页面即可继续操作。

**操作反馈：**

所有互动操作都应给予用户即时且明确的反馈：

- 操作成功时，按钮状态和数值应实时更新（乐观更新），同时可辅以短暂的提示信息。
- 操作失败时，应回退 UI 状态，并给出明确的错误提示。
- 对于删除类操作（如删除评论），必须提供二次确认弹窗，防止误操作。

**防重复操作：**

- 连续快速点击点赞按钮时，只应产生一次有效的点赞或取消点赞操作。
- 评论提交后，在请求完成前应禁用提交按钮，防止重复提交。

**权限控制：**

- 用户只能删除自己的评论，不能删除他人评论。
- 用户不能关注自己。
- 用户不能给自己的文章点赞（可选规则）。
- 被封禁或禁言的用户不能执行任何互动操作（评论、点赞、收藏、关注、私信）。
- 管理员有权删除任何不当评论，无需征得用户同意。

**数据一致性：**

- 文章的点赞数、收藏数、评论数应始终与实际的点赞记录、收藏记录、评论记录保持一致。
- 当用户取消点赞/收藏/关注时，对应的计数应准确减一。
- 当评论被删除时，文章的评论计数应准确减一。

**通知触发：**

| 互动行为 | 通知对象   | 通知内容示例                  |
| :------- | :--------- | :---------------------------- |
| 评论文章 | 文章作者   | “XXX 评论了您的文章《YYY》”   |
| 点赞文章 | 文章作者   | “XXX 点赞了您的文章《YYY》”   |
| 关注作者 | 被关注者   | “XXX 关注了您”                |
| 收到私信 | 私信接收方 | “您收到了一条来自 XXX 的私信” |

> 用户不应收到自己行为触发的通知（如自己评论自己的文章，不给自己发通知）。


## 8. 数据分析模块

### 8.1 模块概述

数据分析模块负责对平台中发生的各类用户行为、内容表现和业务数据进行采集、聚合、统计和可视化展示。该模块将平台中零散的操作记录转化为有价值的洞察，帮助普通用户了解自身影响力、帮助作者优化创作方向、帮助管理员把握平台整体运营状况。

数据分析模块本身不产生业务数据，而是依赖用户认证、内容管理、用户交互等模块产生的行为数据进行二次加工和呈现。

### 8.2 数据采集

**采集范围：**

| 事件     | 说明                 | 触发时机         |
| :------- | :------------------- | :--------------- |
| 用户注册 | 用户完成账号注册     | 注册成功后       |
| 用户登录 | 用户成功登录系统     | 登录成功后       |
| 浏览文章 | 用户进入文章详情页   | 文章详情页加载时 |
| 发布文章 | 用户成功发布一篇文章 | 文章发布成功后   |
| 发表评论 | 用户发表一条评论     | 评论提交成功后   |
| 点赞文章 | 用户点赞一篇文章     | 点赞操作成功后   |
| 收藏文章 | 用户收藏一篇文章     | 收藏操作成功后   |
| 关注作者 | 用户关注一位作者     | 关注操作成功后   |
| 发送私信 | 用户发送一条私信     | 私信发送成功后   |

**采集内容：**

每条行为事件应记录以下信息：

- **行为主体**：执行该操作的用户 ID（如果是游客浏览文章，用户 ID 可为空）。
- **行为类型**：具体是哪一类事件（如“浏览文章”“点赞文章”等）。
- **行为目标**：该行为作用于什么对象（如某篇文章、某个用户、某条评论）。
- **行为目标 ID**：目标对象的唯一标识。
- **发生时间**：行为发生的精确时间。
- **环境信息**（可选）：请求的 IP 地址、浏览器 User-Agent、来源页面等。

**采集方式：**

- 行为事件的记录应在后端业务接口中同步或异步完成。
- 行为事件的记录不应影响主业务流程的性能和稳定性，建议采用异步写入的方式。
- 对于浏览文章事件，需做去重处理：同一用户在较短时间内（如 5 分钟）多次浏览同一篇文章，只记录一次有效浏览。

### 8.3 个人数据看板

**目标用户：** 所有已登录的普通用户和作者。

**核心指标展示：**

用户进入个人数据看板时，应看到以下核心指标的汇总数据：

- **总阅读量**：用户所有已发布文章累计获得的阅读次数。
- **总点赞数**：用户所有已发布文章累计获得的点赞总数。
- **总收藏数**：用户所有已发布文章累计获得的收藏总数。
- **总评论数**：用户所有已发布文章累计获得的评论总数。
- **新增粉丝数**：用户在最近一段时间内（如近 30 天）新增的关注者数量。
- **文章发布数**：用户已发布文章的总数量。

上述指标应以 KPI 卡片的形式清晰展示。

**时间范围筛选：**

- 用户可以对看板中的数据进行时间范围筛选，查看不同时间段内的数据表现。
- 系统应提供快速筛选选项：近 7 天、近 30 天、近 90 天。
- 系统也应支持自定义时间范围选择，用户可自由选择起始日期和结束日期。
- 切换时间范围后，看板中所有图表和卡片数据应同步更新。

**阅读趋势图：**

- 以折线图的形式展示用户在选定时间范围内的每日阅读量变化趋势。
- 横轴为日期，纵轴为阅读次数。

**互动趋势图：**

- 以折线图或多线图的形式展示用户在选定时间范围内的每日点赞数、收藏数、评论数变化趋势。
- 三种互动数据可以在同一图表中展示（多线对比），也可以分别展示。

**热门文章排行：**

- 展示用户所有文章中表现最好的前 N 篇（如 Top 5 或 Top 10）。
- 排序维度可支持：按阅读量排序、按点赞数排序、按收藏数排序、按评论数排序。
- 每篇文章应展示：文章标题、发布时间、阅读量、点赞数、收藏数、评论数。
- 点击文章标题可跳转至文章详情页或文章编辑页。

**文章数据明细：**

- 以表格形式展示用户所有文章的数据明细。
- 表格列应包括：文章标题、发布时间、文章状态（已发布/草稿/审核中）、阅读量、点赞数、收藏数、评论数。
- 表格应支持分页展示。
- 表格应支持按不同列排序（如按阅读量排序、按发布时间排序）。

### 8.4 运营总览看板

**目标用户：** 系统管理员。

**核心指标展示：**

管理员进入运营总览看板时，应看到以下核心指标的汇总数据：

- **注册用户总数**：平台累计注册用户数量。
- **新增用户数**：选定时间范围内新增注册用户数量。
- **日活跃用户数**：选定时间范围内每日活跃用户数量。
- **文章总数**：平台累计已发布文章数量。
- **新增文章数**：选定时间范围内新增发布文章数量。
- **评论总数**：平台累计评论数量。
- **点赞总数**：平台累计点赞数量。
- **收藏总数**：平台累计收藏数量。
- **私信总数**：平台累计私信数量。

上述指标应以 KPI 卡片的形式清晰展示。

**时间范围筛选：**

- 管理员可以对看板中的数据进行时间范围筛选。
- 系统应提供快速筛选选项：近 7 天、近 30 天、近 90 天、今年以来。
- 系统也应支持自定义时间范围选择。

**用户增长趋势图：**

- 以折线图展示选定时间范围内每日（或每周）的新增用户数变化趋势。
- 可同时叠加展示累计用户数的变化曲线。

**内容增长趋势图：**

- 以折线图展示选定时间范围内每日（或每周）的新增文章数和新增评论数变化趋势。
- 可以在同一图表中展示两条曲线，也可以分别展示。

**互动行为分布：**

- 以饼图或柱状图展示选定时间范围内各类互动行为（点赞、收藏、评论、关注、私信）的数量分布。

**全站热门文章排行：**

- 展示全站范围内表现最好的前 N 篇文章（如 Top 10）。
- 排序维度可支持：按阅读量排序、按点赞数排序、按收藏数排序、按评论数排序。
- 每篇文章应展示：文章标题、作者昵称、发布时间、阅读量、点赞数、收藏数、评论数。
- 点击文章标题可跳转至文章详情页。

**活跃用户排行：**

- 展示选定时间范围内最活跃的前 N 名用户（如 Top 10）。
- 活跃度的衡量标准可以是：发布文章数、发表评论数、获得点赞数等。
- 每个用户应展示：用户头像、昵称、主要活跃指标数值。

### 8.5 约束与边界

- 数据分析模块不负责主动干预业务行为，只负责记录和呈现数据。
- 数据分析模块不负责发送通知，通知的发送由通知消息模块负责。
- 数据分析模块的数据来源是各业务模块产生的业务数据和行为事件记录，模块内部不应直接修改业务数据。

**非功能需求：**

- **数据准确性**：统计看板中的所有数据指标，必须与实际业务数据保持一致。
- **数据实时性**：核心指标应保持较高实时性，趋势图等聚合统计允许一定延迟，但需在页面中说明数据更新时间。
- **查询性能**：看板页面的数据加载时间应在可接受范围内（如 3 秒以内）。
- **权限隔离**：个人数据看板只能展示当前登录用户自己的数据。运营总览看板只能由管理员访问。
- **空数据状态**：当用户还没有任何数据时，看板页面应展示友好的空状态提示。
- **移动端适配**：看板中的图表和卡片在移动端应能正常展示。

### 8.6 模块协同关系

用户交互模块和数据分析模块之间存在紧密的协同关系：

- **用户交互模块产生数据**：用户执行评论、点赞、收藏、关注、私信等操作时，这些操作既是交互行为本身，也是数据分析模块需要采集的原始数据。
- **数据分析模块反哺交互体验**：数据分析模块统计的点赞数、收藏数、评论数等数据，需要在文章列表、文章详情等页面中展示，这些展示直接影响用户的交互决策。
- **个人中心作为交汇点**：个人中心是用户交互模块和数据分析模块的共同入口，两个模块的功能在个人中心中统一呈现给用户。
